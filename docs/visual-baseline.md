# Tien OS visual baseline

**Decision date:** 2026-08-01

**Decision:** Use [`react-rnd@10.5.3`](https://www.npmjs.com/package/react-rnd/v/10.5.3) as the pinned, headless drag/resize baseline, while keeping the domain reducer, accessible shell, and contemporary visual material project-owned. Do not fork a Tahoe replica or put a liquid-refraction engine in the critical path.

This is the bounded implementation-time check required before choosing the macOS 26 / Tahoe-inspired treatment. It supplements the broader historical research; it is not permission to copy Apple's assets or another project's trade dress.

## Search and verification scope

The check covered four focused web searches (`macOS 26 Tahoe web clone GitHub`, `Liquid Glass React UI library GitHub license`, `macOS Tahoe portfolio web desktop`, and `CSS liquid glass effect accessibility performance`) and GitHub repository searches for Tahoe shells, React liquid-glass libraries, and CSS kits. Repository status, exact refs, trees, licenses, package metadata, CI, and contributors were verified with `gh-axi`. Strong live examples were inspected with `chrome-devtools-axi` at 1440×900 and 390×844.

This deliberately small scope answers the implementation question: is there a current, responsibly adoptable React/Astro baseline or material primitive? It does not reopen the approved app architecture.

## Implementation conclusion

No checked candidate is safe as a complete OS shell, and no dedicated liquid-glass package is mature enough for the initial critical path. The closest material library (`@samasante/liquid-glass`) is promising, but its v0.1 single-maintainer status, lack of behavior tests, 390 px demo overflow, and copied-node/WebGL modes do not save effort for shell chrome.

A focused reuse does save effort: Tien OS pins the MIT-licensed `react-rnd@10.5.3` at upstream ref [`fec7303134ab0f0bbe83fdf975ddc15c340f7e5d`](https://github.com/bokuweb/react-rnd/tree/fec7303134ab0f0bbe83fdf975ddc15c340f7e5d) for controlled drag, transform movement, bounds, and eight-way resize. During a resize, the frame mirrors the package's returned position and element dimensions into component-local draft state; it commits the resulting rectangle to the reducer once on stop and clears the draft. This is substantial upstream behavior reuse without a global state update per pointer move. Tien OS continues to own unique IDs, focus/z-order, maximize/minimize, persistence, routes, mobile collapse, semantic controls, and accessible keyboard commands. The package receives no authority over app state and is disabled entirely in the mobile single-surface path.

The visual material remains a self-authored approximation of the **principles**, not Apple's pixels:

- layered translucent surfaces using bounded `backdrop-filter` blur, tint, subtle borders, and a solid high-contrast fallback;
- Golden Gate coastal dusk wallpaper drawn entirely in CSS and inline SVG (gradient sky, sun, haze, bridge cables/towers/deck, sea, shimmer, vignette) rather than a copied wallpaper image;
- slim edge-to-edge menu bar, compact translucent Control Center, centered magnifying dock, and window traffic lights rendered as original inline SVG glyphs on plain colored circles;
- restrained transform/opacity motion (dock bounce and magnification, window minimize, snap glide), disabled for reduced motion and coarse/mobile interaction;
- system fonts and original inline SVG app glyphs;
- mobile single-surface navigation rather than a shrunken desktop;
- no refraction JavaScript, WebGL, remote imagery, candidate CSS, or candidate assets in the shell.

This split is the smallest reuse-first baseline that survives the project gates: mature headless window mechanics are reused; identity, material, semantics, responsive policy, and state remain asset-clean and testable.

The visual implementation must continue to pass the repository's bundle, no-third-party-requests-on-initial-shell-load, provenance, responsive overflow, reduced-motion, contrast, and axe gates. If a true refractive lens is proposed later, benchmark it as an app-level enhancement rather than placing it in the shell critical path.
