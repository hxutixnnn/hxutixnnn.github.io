# Maintenance architecture audit

Audit baseline: `74b5e6e` after PRs #32–#38.

## Findings implemented

- **Unit-test flake control.** A full `pnpm validate` failed after 125.38 seconds because the interaction-heavy System Settings persistence test exceeded Vitest's 5-second default; the same test took 3.48 seconds in isolation. A 10-second suite timeout keeps the assertion and gives parallel-load headroom rather than retrying or weakening it. With the change, all 174 tests passed in a 118.05-second `pnpm validate` run on the same host (7.33 seconds faster, although the primary result is removal of the false failure rather than a performance claim). CDP screencast frames also arrived with adjacent fade samples out of opacity order in two full-suite runs; the startup contract now rejects an opaque splash flash after desktop exposure begins instead of requiring unreliable sample-by-sample monotonicity, while retaining blend-residual, exposure, and final-opacity assertions.
- **PR critical path.** Browser tests and three-run Lighthouse collection were serialized after quality checks despite consuming the same immutable `dist/`. CI now publishes that checked output once and runs those independent gates in parallel, then packages that exact artifact. This removes one whole browser-gate duration from the post-build critical path. Main previously ran the complete Validate workflow concurrently with the equally complete Pages workflow; Validate is now PR-only, while Pages remains the authoritative post-merge validation and deployment.
- **Preview correctness.** Standalone `pnpm test:e2e` previously previewed whichever `dist/` happened to exist. Its owned preview now builds first. CI's explicit skip is safe only because it downloads (PR) or just produced (Pages) the validated build.
- **Retired tooling and dependencies.** `validate-apps.mjs`, `sync-repositories.mjs`, and `finalize-sitemap.mjs` entered with the retired Astro catalogue architecture. History and repository-wide caller searches found no caller after the Vite reset; `validate-apps.mjs` also imported catalogue files that no longer exist. Removing them removes the sole direct Zod use, and Zod's incorrect production classification. Unused `serve` and `@tailwindcss/cli` development dependencies were also removed; Vite preview and `@tailwindcss/vite` remain the active tools.
- **Documentation accuracy.** The unreleased changelog claimed a `/preview/` gallery that the current Vite application does not ship. It now describes the current release, and the browser-test documentation states the build/preview contract.

## Complexity deliberately retained

- The five Playwright spec boundaries and all meaningful assertions remain intact. PR #32 reduced one 4,406-line spec into regression-owned files; the two large appearance/lifecycle contracts still reflect distinct, stateful browser surfaces. One later assertion that the window was _still_ minimizing after fixed 300 ms + 150 ms waits was removed after it raced to `minimized`; the same test already captures and asserts the `minimizing` state, inertness, accessibility state, moving Dock target, and final minimized status, so the fixed-time duplicate had no unique regression value. No visual baseline was removed.
- The static and React shells intentionally duplicate first-paint presentation. Moving first paint behind JavaScript would weaken failure behavior. `check-static-output.mjs` validates useful, local, canonical production HTML; `check-appearance-bootstrap.mjs` executes the inline bootstrap across persisted modes and compares its observable result with runtime definitions; startup Playwright coverage checks static-to-runtime replacement. Those parity gates are preferable to introducing a generator for one root route.
- Zod was removed only because its validator and all inputs are retired. If multi-app catalogue metadata returns, schema validation should return as build tooling (a development dependency), with one catalogue feeding routes, launch policy, and static output rather than parallel lists.
- macOS interaction behavior was not changed by this audit, so no speculative interaction churn or new platform interpretation was needed.
